En una frase: tomamos BERT-base, que ya sabía inglés, y lo entrenamos con SQuAD 2.0 para que señale la respuesta dentro de un texto o diga "no sé" (null) cuando el texto no la contiene.

Todas las métricas se calcularon sobre 500 preguntas de validación de SQuAD. El test oculto del profesor usa textos distintos, así que se espera algo menos.

Umbral de "sin respuesta"

¿Para qué sirve esta pestaña?Explica cómo el modelo decide decir null. Es la parte más preguntada: el reporte pide "cómo elegimos el umbral", el pitch lo evalúa como decisión clave y es candidata a pregunta del Q&A.

Para cada pregunta se calculan dos puntajes crudos (logits):

  • s_null: qué tan convencido está el modelo de que no hay respuesta (token [CLS]).
  • s_best: qué tan convencido está de que el mejor fragmento del texto es la respuesta.
diff = s_null − s_best
si diff > tau → answer = null
si no → answer = mejor fragmento

El umbral calibrado en validación es tau = −2.25, el valor que maximizó el F1.

Grupodiff medioLectura
Preguntas con respuesta−4.66El modelo prefiere el fragmento.
Preguntas sin respuesta+2.45El modelo prefiere decir "no sé".

La separación de unos 7 puntos entre los dos grupos es lo que permite que el umbral funcione.

Próximos pasos

¿Para qué sirve esta pestaña?Es la lista de lo que falta para la entrega, según el cronograma de la guía, para saber qué hacer después.
  1. Descargar modelo_guardado de Colab (o de Drive) a la laptop.
  2. Hacer la API con FastAPI con /health, /info y /predict, siguiendo el contrato. El token se lee de QA_API_TOKEN y nunca se escribe en el código.
  3. Resolver el bloqueo de Windows con la librería tokenizers (WSL es la salida más segura) para poder correr el modelo en la laptop.
  4. Probar con public_sample.json y volver a medir la latencia en la laptop, ya con el túnel.
  5. Dry run y entrega: tag submission en git, historial sin aplastar, pesos fuera de git.
  6. Escribir REPORT.md con todas las secciones llenas. Si falta, la nota final se reduce a la mitad.
